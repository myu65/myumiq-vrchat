# 動作名によらない身体目標

「しゃがむ」「手を上げる」を一つずつ増やす代わりに、到達したい状態を
条件として渡す。例えば「頭を8cm低くし、両足の位置を保つ」や
「その高さで左手を少し前へ出す」を同じ経路で扱う。

## 実装した経路

```text
BodyGoal.conditions（部分的な位置・向き）
  → 現在姿勢・計測対象への結び付け
  → 全身の目標補完（既存の骨格・関節範囲・床を検査）
  → 既存の学習済みactor
  → MotionBuffer / 既存の出力合成
  → 観測した条件達成の評価
```

条件は全身について同時に解く。指定していない成分は自由とし、現在の姿勢に
近い解を優先する。手だけの出力上書きや動作別の制御器は追加していない。
目標補完は数値最適化であり、学習済みの動作事前分布ではない。
関節範囲内の骨格でも自然な姿勢や自己衝突の回避を保証するものではない。

補完は既存のmotor準備worker上で行い、通常3秒で打ち切る。主ループは現在姿勢を
保持して会話・観測・出力を続ける。条件の変更や停止で古い計算を取り消し、
終了確認前に次の計算を重ねない。補完途中の値は身体出力に使わない。

新しい目標を明示的に受けたときは、前の動作を保持状態へ移して準備する。
到達後はその姿勢を保持し、雑談で既定姿勢に戻さない。準備期限と実行期限は別である。
目標が作れたこと、actorが到達できたこと、avatarが自然に見えたことを分けて記録する。

## 設定と入力

外部の`ArticulatedTasks`設定で`condition_goals: true`を指定する。
actor・rigのhash、床、通常の出力所有・観測の条件は既存設定を使う。
条件入力だけの設定なら`goals`は空でもよい。既存の名前付き目標も併用できる。
標準では無効で、現在の入口は実行中consoleの`body_goal`コマンドである。
**会話LLM・plannerが任意の条件を生成する接続は、まだ実装していない。**

同じCLIへ渡す入力の例：

```json
{
  "kind": "body_goal",
  "body_goal": {
    "duration_s": 12.0,
    "conditions": [
      {"part": "head", "frame": "current", "position": [null, null, -0.08]},
      {"part": "left_foot", "frame": "current", "position": [0.0, 0.0, 0.0]},
      {"part": "right_foot", "frame": "current", "position": [0.0, 0.0, 0.0]}
    ]
  }
}
```

`body_console send --session <実行中のsessionフォルダー> <JSON文字列>`で送る。
受理は動作完了を意味しない。`intent.execution`の状態と
`intent.articulated_actor.goal_evidence.condition_evidence`で判定する。
`goal_evidence`は到達時の観測記録で、現在の接触や対象の状態を証明しない。
条件付きactorが有効でない場合は拒否する。

| 指定 | 意味 |
| --- | --- |
| `part` | 頭・胸・骨盤・左右の手、肘、膝、足の11部位 |
| `position` | X=前、Y=左、Z=上のメートル値。`null`成分は制約しない |
| `frame: tracking` | 計測座標系での絶対位置 |
| `frame: current` | 準備開始時に観測した同部位からの差分。毎フレーム加算しない |
| `frame: target` | `target`名で特定した計測対象の位置からの差分 |
| `orientation` | 正規化したwxyz quaternion。省略すると向きを制約しない |
| `position_tolerance` | 指定成分の合成誤差。標準3cm、設定範囲0.5〜12cm |
| `angular_tolerance` | 回転誤差。標準0.15rad、設定範囲0.02〜0.35rad |

全frameの位置差分は計測座標軸を使い、関節のローカル軸ではない。
`current`の回転は計測座標系の差分として左から掛ける。
`target`には対象の向きの観測がないため、指定した回転は絶対回転である。
VRChatのワールド移動量をtracker位置へ加算しない。

1部位につき1条件、最大11条件。旧`tasks/constraints`との混在は拒否する。
consoleの実行時間は1〜20秒。1.5m超の位置変更と、補完による0.75m超の
骨盤移動は現在の対応範囲外とする。許容値内でも達成可能とは限らない。

対象基準は、単一ID・計測座標・0.5秒以内の時刻・信頼度0.5以上を必要とする。
現在は`fixture/manual`の校正済み入力だけを受け付け、`vision`の画像枠から
推測した位置は使わない。実行中の対象消失・古い観測・1cm超の対象移動では
追従せず保持して終了する。継続追従には新しい観測を使う別の拡張が必要。

## 名前を登録していない条件の評価

`condition_validation`は目標補完と実際のactorの実行を別々に評価する。
名前付き姿勢は開始状態だけに使い、目標は任意の条件値・組合せとする。
記録した全身姿勢を開始点にする場合は`start`を省略し、`start_pose`に
11部位を持つ`BodyTarget`を指定できる。身体入力は中立とし、宣言した床を検査する。
練習のために新しい動作名を実機の能力一覧へ登録する必要はない。

```json
[
  {
    "id": "lower-and-reach",
    "start": "STAND",
    "split": "heldout",
    "goal": {
      "duration_s": 12.0,
      "conditions": [
        {"part": "head", "frame": "current", "position": [null, null, -0.1]},
        {"part": "left_hand", "frame": "current", "position": [0.07, 0.0, 0.0]},
        {"part": "left_foot", "frame": "current", "position": [0.0, 0.0, 0.0]},
        {"part": "right_foot", "frame": "current", "position": [0.0, 0.0, 0.0]}
      ]
    }
  }
]
```

```powershell
python -m myumiq_vrchat.condition_validation `
  --tasks ../artifacts/tasks.json --cases ../artifacts/conditions.json `
  --out ../artifacts/condition-evaluation
```

出力先は新しい外部フォルダーを指定する。`result.json`に入力・actor・rigのhash、
補完条件、actorの終点、条件誤差を保存する。1例でも未達なら終了コード1を返す。
全点の通常許容誤差に加え、元の各条件も満たして保持できた場合だけ成功とする。
`split`は実験の分割ラベルであり、それだけで既存モデルの学習データとの
独立性を証明しない。この評価自体は学習や重み採用を行わない。

## 条件からの練習と残る汎用化

条件値と開始姿勢を分けた候補学習は`condition_training`で実装した。
元の条件誤差を学習目的に含め、途中状態からの練習、既存姿勢の復習、
足のずれと急な加減速の退行検査を行う。詳細は
[人間らしい動きの練習と検証](human-motion-practice.md)を参照する。
これは予測モデル内の練習であり、鏡画像から報酬を得る自動学習ではない。

残る範囲は次のとおり。

1. 身体判断側が観測に根拠のある条件を提案し、同じ検証・実行経路へ渡す。
   会話出力から関節命令を取り出さず、会話の待ち条件にも追加しない。
2. 実機の失敗を、観測の信頼度と見た目の評価を保って次の課題へ自動変換する。
   現在の課題選択はoperatorが行う。機械的な条件達成と自然さを混同しない。
3. mask付き条件を直接受けるactorを比較する。今回の全身目標補完は、現行actorを
   変えずに実行可能性を測るためのadapterであり、最終的な学習方式を固定しない。
4. 軌道・接地・対象追従・接触の条件を観測可能な範囲から追加する。
   うつ伏せへの移行や「なでる」は終点の位置だけでは成立しない。

これらは未実装の段階である。既存の候補学習・検査・採用の境界を保ち、
動作名を追加したことや骨格の終点が解けたことを、新しい技能の獲得と呼ばない。
