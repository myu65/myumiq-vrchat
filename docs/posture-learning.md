# 姿勢・対人動作の学習計画と実装範囲

動作名を増やす先の入口として、[部分条件による身体目標](body-conditions.md)を
実装した。頭の高さ・手の位置・足の維持などを同時に指定し、既存actorへ渡す。
以下の名前付き姿勢・参照は引き続き互換入力として使える。

会話は今の姿勢を解除しない。身体モデルは全身の目標に向かって動き、
到達後は新しい身体要求または停止まで保持する。VRChatの静止状態に
重力に抗うトルク制御を追加する必要はない。

## 実装した範囲

| 対象 | 現在の実装 | まだ必要な検証・入力 |
| --- | --- | --- |
| しゃがんで話す | CROUCHと会話の寿命を分離。雑談・非対応依頼・確認待ちでは姿勢を解除しない | 人から見た姿勢と音声の同時確認 |
| 新しい姿勢 | `POSTURE_*`を静止全身目標または有限の動作参照として設定できる | そのactorで移行・保持・復帰できる根拠 |
| うつ伏せ | 全身actorの候補学習・床検査・姿勢間評価の経路 | 適切な伏臥・起き上がり参照、既存技能の退行検査、実機確認 |
| なでる | 不足能力を明示し、画像上の対象だけでは実行しない | 対象の頭の実測位置、対象追跡、到達・接触・終了の評価環境 |

`LIE`の診断姿勢は仰向けであり、うつ伏せの代用にしない。
モデルの損失低下、参照の補間精度、実際の姿勢移行、相手に触れたことは別の結果として扱う。

## 設定と学習

既存の`ArticulatedTasks.goals`に完全な11点の目標を追加し、同名の説明を
`descriptions`へ指定できる。例えば`POSTURE_PRONE`と「うつ伏せになって姿勢を保つ」。
単なる名前の追加では運動能力は増えない。actor・rigのhashと床の設定を一致させる。
静止目標と動作参照の同名定義は不可。両者は合計32項目まで。

`motions`または`purpose.learning.motions`の`POSTURE_*`には有限の参照を使う。
周期運動は受け付けない。参照作成例：

```powershell
python -m myumiq_vrchat.motion_training ../artifacts/motion.glb `
  --license ../artifacts/LICENSE.txt --source-url https://example.org/source `
  --clip ProneToStand --kind finite --reverse --out ../artifacts/prone-reference
```

これはライセンス確認済み資産の例であり、同名の素材は同梱していない。
`--reverse`は元の両端の姿勢と時間間隔を保って逆再生する。逆再生だけで
自然な接地順序を保証するものではない。設定側は`kind: "finite", reverse: true`。

自動学習した姿勢参照は`candidate_pending_validation`として保存され、
稼働中または再起動後の身体へ自動登録しない。既存actorで実行可能な範囲の
ジェスチャー参照の獲得と、未学習の姿勢をactorへ追加する作業を混同しない。
評価してから明示的にcatalogueへ登録し、実機では限定した試験を行う。

## actorを評価する

実際のactor重みを読み、静止姿勢の全組合せを理想的な出力応答の下で検査する：

```powershell
python -m myumiq_vrchat.posture_validation `
  --tasks ../artifacts/tasks-candidate.json --goals STAND CROUCH POSTURE_PRONE `
  --out ../artifacts/posture-evaluation
```

開始姿勢から全身関節を推定し、観測点と骨格の残差を維持する。
各trackerの位置誤差12cm以内・回転誤差0.35rad以内が150ms以上続けば到達保持とする。
開始・提案姿勢の頭、胸、骨盤、手、肘、膝、足が宣言した床を下回れば不合格。
同一姿勢の保持に成功しても、その姿勢になる能力の根拠にはならない。
結果は実機、avatarのIK、身体表面の衝突・接触の検証ではない。
`result.json`にはactor・rig・入力設定のhashを保存し、不合格なら終了コード1を返す。

学習候補は既存PAMIQ `ExperienceRefinementTrainer`で更新できる。
姿勢実験用の`whole_body_floor=True`は、既存の足の罰則に頭・手などの床余裕を加える。
学習中の予測は実機経験と区別し、推論用モデルと自動同期しない。
静止姿勢の検査に加え、歩行・手振りの全区間評価を通るまで運用actorを置き換えない。

## 次の実装順序

1. 伏臥と復帰を含む適切な参照を確保する。立位の全身を回しただけの目標は
   合成実験として記録し、自然なうつ伏せの教師データとは呼ばない。
2. 失敗直前の姿勢を含む段階的な候補学習で、立位・しゃがみ・伏臥間の移行を通す。
   平均誤差だけで採用せず、床違反と既存動作の退行を検査する。
3. なでる練習は計測できる対象から始める。対象ID、座標系、時刻、信頼度、
   メートル単位の頭の位置と向きを観測アダプターで提供する。
   自分のOpenVR trackerや相手の2D画像枠を、相手の頭の3D観測として流用しない。
4. 同じ全身actorへ対象基準の到達・往復・離脱の参照を与える。対象消失時は
   追従を止める。接触の証拠がない環境では「対象付近で手を動かす」評価にとどめる。
5. 相手の確認を得られる実機試験で、目標保持中の会話、途中停止、対象移動、
   対象消失、動作終了を確認する。

`PAT_HEAD`の不足条件は`TARGET_IDENTITY`、`TARGET_HEAD_POSE`、`REACH`、
`CONTACT_FEEDBACK`、`PARTNER_CONSENT`として既存の能力管理へ返す。
これらの名前は観測実装の代わりではなく、現時点では未提供のものがある。
