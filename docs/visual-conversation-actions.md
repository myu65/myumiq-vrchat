# 視界・会話・行動をつなぐ

## 整理した課題

| 問題 | 変更 | 残る制約 |
| --- | --- | --- |
| 会話が人物IDの一覧しか受け取らない | 知覚workerが作った画像と同時刻の世界状態を、会話・身体判断・目的提案へ渡す | 静止画であり、連続動画理解ではない |
| 実行できない動作にも了承する | 判断モデルが要求された能力を先に明示し、実行管理が能力表で検証。会話へ採否と実行状態を渡す | 自由文の解釈・返答品質はモデル評価が必要 |
| 直進要求でも探索の旋回を続ける | 短い直進・左右旋回を別の候補とし、方向を途中で探索規則へ変更しない | 経路計画、追従、角度指定、一回転は未対応 |
| 雑談で姿勢や移動の目的が変わる | 明示的に採用された姿勢・直進/旋回要求を保持。有限実行後は保持し、勝手な探索へ戻さない | 任意の複合全身Goalや長距離移動は未実装 |
| 終了に応じた後も自動動作が続く | 停止を身体側で保持し、次の実行可能な身体要求まで自発動作・Plannerを抑止 | VRChatアプリや試験supervisorの終了とは別 |
| 完了後に一時的な観測欠落で「実行不可」に書き換わる | 採用済み依頼の実行記録は観測結果だけで更新。現在の能力判定と分離する | 実行証拠の範囲を超えた成功は主張しない |
| 画像説明の名詞を実在する操作対象IDと扱う | Plannerのfocusを既知の対象・能力IDに制限し、受信後も検証する | 名前や画像説明だけから座標・対象対応を創作しない |
| 低確度・古い人物候補を現在の相手と扱う | 古い/低確度の検出を除外し、画像付き判断で対象を照合。交差時に曖昧なIDを引き継がない | 匿名trackは話者・ユーザー本人を保証しない |
| 観測更新が失敗後の待ち時間を消す | 推論失敗の再試行期限を、通常の観測更新とは別に保持 | サービス側の制限や障害自体は別問題 |

## 実装上の流れ

1. 既存の知覚workerが画像を圧縮し、時刻付き世界状態と一緒に公開する。
2. `visual_context` が鮮度を検査する。検出がゼロでも画像は渡せる。
3. 身体判断は現在の画像・会話・能力表・実行結果から、要求能力と候補を提案する。
4. `PurposeRunner` が対象・能力・停止・保持条件を検証し、既存の身体実行器へ渡す。
5. 会話は身体判断と並行して直ちに生成を開始する。画像・能力・現在ある実行証拠を渡す。
   判断未完了は `parallel_pending` とし、雑談や視覚質問への回答を妨げない。
   動作の採用・成功は推測しないよう指示する。自由文の約束を完全に防ぐ保証はなく、
   会話の返答が身体への実行権限になることはない。
   旧来の待機・定型の確認中返答・一回の追加返答は明示設定した互換経路に限定する。
6. 身体は音声生成を待たずに動く。結果は共有記憶と試験記録に戻る。

画像を送るかどうかはモデルの役割ごとに設定する。古い画像や未取得の視界を
現在の観測と扱わない。会話・Plannerの送信記録には画像の時刻・ハッシュ・利用有無を
残し、画像本体は記録しない。画像内の文章は命令ではなく観測内容である。

## 設定

`myumiq models init --profile openrouter-vision --output <外部の設定ファイル>`
で会話・判断・Plannerに画像を使う例を生成できる。従来のlocal/openrouter/hybridも残す。
任意のローカル/APIモデルは従来通り `--profile-file` とgeneration adapterで交換できる。
画像対応はモデル名だけで判断せず、**選択した接続先が画像と構造化出力を同時に
受け付けること**を確認する。モデルと接続先は試験開始時に固定し、実行中の自動切替はしない。

- `dialogue.use_image`: 会話への画像添付。画像非対応モデルではfalse。
- `dialogue.max_image_age_s`: 会話画像の有効期限。
- `dialogue.await_body_assessment`: 旧待機経路の選択。既定false。
- `dialogue.action_wait_s`: 旧経路だけに適用する身体判断の待機上限。
- `dialogue.action_followup_s`: 旧経路だけに適用する追加返答の待機上限。
- `dialogue.stream_sentences`: 一文単位の音声送信。既定true。SSE非対応runtimeではfalseを指定。
- `decision.selection.use_image`: 身体判断への画像添付。
- `decision.selection.understand_requests`: 要求能力の抽出・採否を使う。
- `decision.selection.allow_state_only`: 画像未取得時に状態だけの判断を明示的に許す。
- `purpose.planner_use_image`: 目的提案への画像添付。

ローカルのテキスト専用モデルにも能力表と採否は渡せる。画像を有効にする場合は
そのモデルを提供するruntimeにも画像対応が必要。認証値は設定例に含めず、従来の
環境変数参照を使う。端末別の接続結果・計測値・採用設定はリポジトリ外へ保存する。

## 動作の意味

`MOVE_FORWARD` / `TURN_LEFT` / `TURN_RIGHT` は、既存の許可されたHome、
新しい画像、歩行方策、短いcontroller出力の許可が揃ったときだけ利用可能。
通常の `exploration.mode=continuous` はGoalの有限な実行期間中、出力leaseを更新する。
0.35秒pulseと約1秒settleの旧動作は `mode=pulse_test` に限定する。
30Hzのcontrollerが加減速を制限し、同じ要求状態をスティックと歩行参照の速度へ渡す。
actorのreadback待ちやそのフレームの学習metadata欠落だけでは移動入力を切らない。
歩行参照自体のreadback確認はまだ残っており、20Hz actor/horizon化とは別の段階である。
姿勢とcontroller移動の両方を既存の単一身体出力から送る。カメラ欠落、
期限切れ、明示停止、Home変更時には移動入力を解放する。
音声入力開始は返答だけを取り消し、身体Goalと移動leaseを消さない。
「止まって」等の曖昧さのない単独の停止要求はローカル実行管理で即時に受け付ける。
引用・否定・説明文を単純なキーワード一致で停止へ変換しない。
方向指定は推論モデルの座標生成ではなく、高次の有限な動作選択である。

画像変化・デバイスreadback・アバターの見た目・相手の受聴を別の証拠として扱う。
現行の直進は短い試行であり、障害物距離を測った安全な経路追従ではない。
FOLLOW、座位/うつ伏せの任意合成、厳密な角度の旋回は、未対応を明示する。
`controller_hz`、`acceleration`、`deceleration`、`continuous_strength`、`turn_strength`
は `exploration` 設定で指定する。速度は正規化された入力値で、m/sやrad/sではない。
旋回のsmooth/snap動作はVRChat側のbindingに依存するため実機で確認する。
モデルが未対応動作を別の動作で代用しようとしても、要求能力の検証で棄却する。
実行済みの依頼は再実行せず、新しい発話IDの依頼だけが再試行を要求できる。
会話モデルの自由文、画像内容の説明、話者同定は引き続き誤り得るため、
それらを身体の成功記録や本人確認の根拠に昇格させない。
