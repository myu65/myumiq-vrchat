# VRChatに合わせた全身学習の再確認

調査日: 2026-09-20。現在の姿勢到達学習は低層の全身制御として利用できるが、
それだけでは歩行・ジェスチャー・新しい技能の自動獲得にはならない。
VRChatでの次の実装は、動作列の事前学習と、世界での結果を使う目的別学習を組み合わせる。
以下の適用判断は論文・公式実装を読んだうえでのMyuMIQ側の設計判断であり、
各研究がVRChatへの直接転用を検証したという意味ではない。

## 近い先行研究

| 研究・実装 | 学習するもの | MyuMIQへの適用 |
| --- | --- | --- |
| [Character Controllers Using Motion VAEs](https://hungyuling.com/character-controllers-motion-vaes/)（SIGGRAPH 2020） | 自己回帰VAEで動作分布を学び、潜在変数を行動として目的別RLを行う | 全身の継続した動作を土台にし、進行方向・目標に合わせて操作する構造が近い |
| [DartControl / DART](https://zkf1997.github.io/DART/)（ICLR 2025） | 直前の身体履歴とテキストから短い全身動作列を生成し、潜在空間の最適化・RLで空間目標を追う | 現在姿勢からジェスチャーや移動へつなげる方向。物理シミュレーションは必須ではない |
| [PAMIQ-VRChat](https://github.com/MLShukai/pamiq-vrchat/blob/main/src/run_sample.py)と[Curiosity Experiments](https://github.com/MLShukai/pamiq-curiosity-exp) | 視聴覚・行動、予測・好奇心を使う実環境の学習ループ | VRChatで経験を集めるループの参照。人型動作の事前知識とは別に必要 |

Motion VAEの[公式コード](https://github.com/electronicarts/character-motion-vaes)には
目標・ジョイスティック・経路・迷路のcontrollerがある。元の訓練モーションは同梱されない。
MyuMIQでは既存のCC0素材を利用し、古い依存環境や実装全体をそのまま組み込まない。

DARTはキネマティックな方式で、床抜け・滑りが残り得る。物理追跡との組合せは追加の
改善策として示されている。また「しゃがむ」など終端のある動作を永遠に生成し続けると
終端付近で揺れる場合がある。動作の完了後に現在姿勢を保持する契約は維持する。
[公式実装](https://github.com/zkf1997/DART)の既成モデルはSMPL系データ等の準備を必要とするため、
現在の11点身体へ直ちに接続できるモデルとして扱わない。

## VRChatの制御境界

[公式OSC Input](https://docs.vrchat.com/docs/osc-as-input-controller)の移動軸は操作入力で、
入力を止めるには0を送る。一方、[トラッカー](https://docs.vrchat.com/docs/osc-trackers)は
身体の位置・回転を伝える。したがって、次を別々に記録・学習する。

- コントローラー入力による移動・旋回。停止時に入力を解除する。
- トラッキング空間のroot移動と全身関節の動き。終了後の標準姿勢へのresetはしない。
- VRChat内で実際に観測できた移動結果。トラッカー目標や入力時間から移動距離を捏造しない。

現在のFK環境の床・速度制限は出力の制約であり、重力下で倒れずに歩く物理RLとは異なる。
トルクでバランスを学ぶ研究を、そのままVRChatの必要条件にはしない。

## 実装を進める順序

1. 現在の全身actorを保持し、姿勢・向き変更の短い実機試験を行う。未操作時の姿勢保持を確認する。
2. CC0の歩行・手振り等を静止姿勢に潰さず、履歴付きの動作列として学習・再生する。
   低層の全身policyと、何の動作をどこへ行うかを決めるtask policyを交換可能にする。
3. controller移動と身体の歩行表現を接続し、視覚変化と観測できる移動状態を分けて経験へ保存する。
4. 不足能力を学習課題にし、既存PAMIQのbuffer/model/trainer・同期・保存を使って
   小さい候補を学習し評価後に登録する。旧policyへ戻せる状態で、実機経験による更新を繰り返す。

会話はこのループへ発話履歴を供給する。音声応答の終了を身体判断や学習開始の条件にしない。
Jev/Gemmaは高次判断と目的提案に使い、毎フレームの関節・コントローラー入力は生成させない。

現在の実装は、設定済み教師からWALK_IN_PLACE・WAVE・MOTION_で指定した追加動作を
自動学習し、全身actorへ登録・保存・再読込するところまで進んだ。有限動作と周期動作を
区別し、別骨格のglTF/GLBも明示的な参照姿勢・joint対応表で変換する。
controller移動と学習済み足踏みも同時実行できる。これは動作事前学習の段階であり、
任意の動作発明や世界の移動報酬によるonline RLを実装したという意味ではない。
研究からの次の拡張は、観測可能なtask rewardを用いる潜在制御の学習となる。
